# 图片方法：参考资产、静帧生成与局部修改

处理静态图：角色设定、身份与状态资产、道具图、空间母版、构图图、局部改图和成图检查。按本文件即可独立完成图片工作，不必读取视频方法。

## 先选本次要交付的图

先根据用户已有信息确定用途：独立成图、角色资产、物件资产、无人场景、构图参考，或已有图的局部修订。用途不同，检查重点也不同；角色多视图用于辨认身份和衣装，不自动承担成图构图。

查看用户指定图片和当前版本。研究用户的 LibTV 项目时先用官方 CLI 读取项目、节点、实际输入和产物；执行 LibTV 操作前读取 `libtv-cli`。仅研究或编写提示词时不擅自生成；用户已有生成授权时直接在授权范围内完成。需要图片生成／编辑时使用内置 `imagegen`，或用户指定的平台；实际使用的工具支持项按当前接口核对。

生成新提示前，从 [原文案例库](verbatim-library.md) 选择主体、景别或任务接近的图片样本并阅读全文。原文单独保存，不补字、不润色；本次新提示和实际提交文本另存。案例中的旧模型名、旧设置和缺漏参数是来源记录，不能直接当今天的能力说明。

## 参考图怎样分工

用 [图片工作单](image-workcard.md) 记下参考图的真实文件／节点、实际输入顺序、负责内容，以及冲突时采用哪张图。只填当前任务需要的项：

| 职责 | 要明确的内容 | 常见冲突 |
|---|---|---|
| 身份 | 脸型、花纹、体型、稳定结构 | 身份图自带旧衣装或旧环境 |
| 当前状态 | 年龄、干湿、服装、背包、姿态 | 同时要求空手与持物、干发与湿发 |
| 物件 | 形状、正反面、材质、数量、持有位置 | 多份参考使手机、餐具或配件重复 |
| 空间 | 建筑、门窗、道路、护栏、固定物与方向 | 换机位被误作镜像或重建场地 |
| 构图 | 主体占比、景别、留白、相互遮挡 | 多视图被照搬成成图布局 |

同一张参考可以承担多个明确职责，不为凑分类强行拆图。两张图给出不同状态时，写出本次采用哪一项；例如“采用 A 的猫脸和花纹，采用 B 的背包款式与背带路线，双爪空置”。参考职责应基于实际图像，不能只相信节点名称。

## 按问题采取动作

| 触发 | 动作 | 检查 | 失败后调整 |
|---|---|---|---|
| 同一角色换装、换道具、跨场景 | 保存稳定身份图，另列当前状态；需要辨认衣装时做正面、侧面或背面视图 | 脸、花纹、体型、衣装附件是否一致；视图间是否混入不同版本 | 回到身份母版，只修改本次状态；旧场景污染身份时可单独提取主体，但须检查提取后外观 |
| 一个名字包含不同年龄、干湿或服装 | 分别命名各状态，当前图只输入适用状态 | 新状态仍可辨认为同一角色；提示所指节点与实际输入一致 | 对照同角度面部与关键服装，必要时从已选母版做状态修改；命名不能代替一致性检查 |
| 要保留场地结构，同时改材质或光线 | 先获得干净空间母版；复杂场景可用去色白模中间版，再调整表面和光线 | 消失点、道路宽度、门窗和固定物位置；去色后结构是否仍清楚 | 若白模已改坏结构，返回原图，缩小改动内容；白模是可选工具，不保证几何不变 |
| 主体应从画面移除，制作空镜 | 明确移除主体及其专属接触阴影、倒影；保留场景应有的光影 | “幽灵”阴影／倒影、地面纹理、遮挡后的补全、原有家具 | 扩大需修补的关联区域，并写清保留项；不把场景全部阴影一并擦除 |
| 文字难以准确指定摆位、尺度或朝向 | 在原构图上提供轮廓、区域或方向标注，另给身份／物件图 | 实际落位、大小、接触面和遮挡；标注是否被保留在成图里 | 调整标注与机位，使位置可理解；让提示明确标注只用于摆位、成图移除标记 |
| 已有画面大体满意，只错一个对象 | 保留原图与版本，只描述本次变化及必须保留的关系 | 修改对象是否正确；主体身份、构图、光线、数量是否被连带改变 | 先缩小修改范围；若问题依赖整体季节、时代或光源，再统一修正相关条件 |
| 图中涉及历史、地点、真实产品或品牌 | 把创作设定与事实要求分开；按需要核验一手材料和官方资产 | 季节与地貌、服装与时代、物件结构、文字、标识来源 | 删除无法支持的细节或标“待核实”；正式 logo、标准字、品牌图形采用确认过的官方资产叠加 |

## 编写与提交

新提示可按“参考职责 → 本次画面 → 只改／保留项 → 摄影意图 → 输出要求”组织，复杂程度随任务调整。局部修改不需要重写整部作品设定；确实影响局部结果的全局条件必须保留。

岑新写并提交的图片提示必须给出具体摄影机型号、镜头类型／系列、焦距、光圈、快门、ISO／EI、白平衡，并写清画幅、景别、机位和对焦；参考 [摄影参数](camera-parameters.md) 按画面目的选数值。参数表达生成画面的摄影意图；实拍元数据和平台实际启用的控制须分别核验。插画、角色表等同样用这些参数明确视角、景深与照明意图，保留用户指定的绘画媒介和风格。

提交前同时核对四样内容：实际输入、提示文本、当前工具设置、准备比较的已有图。清掉旧角色、旧物件、过期状态和矛盾要求；文字中的画幅须与工具设置一致。不要把当前配置、历史提交、产物规格混为一项。

涉及九号官方身份的视觉，先读取工作区 `apply-ninebot-vi`。品牌标识使用清楚的官方或实物参考，保留应有标识，检查形状、文字、位置、比例与透视；不要主动留空或抹除。无来源的产品参考只能作为本次画布的视觉输入，不能证明真实产品结构或官方口径。

## 看结果再决定下一步

对成图实际查看，按本次用途对比原图和参考图：

- 身份／状态图：脸、花纹、体型、年龄、衣装和附件；多视图之间是否一致。
- 场景／构图图：固定物、方向、透视、留白、接触、遮挡；应删除的主体及关联影像是否清理完。
- 物件／品牌图：数量、正反面、结构、材质、文字与官方资产；不能仅凭“看起来像”通过。
- 局部修订：本次要求是否做到，其他已满意内容是否发生意外变化。

确认实际尺寸和比例。分别记录“提示有此要求”“产物已生成”“本次看图观察到”“还未核验”，不要用节点名中的“最终”“高清”代替检查。效果错误时按上表回到最小必要改动；保留原图、修改版、最终提交提示和选用理由，不覆盖历史产物。

本方法的项目依据与观察限度见 [图片案例证据](image-case-evidence.md)。达蒙提供项目和创作目标；岑负责读取、比较、方法提炼和本次执行。原项目具体创作分工以实际记录为准。

# 图片与 LibTV 视频制作

保留一个制作技能，按交付媒介选模块。先读取用户指定素材、脚本、当前节点和已有结果，接续已授权的工作；本次仅写提示或研究时不触发生成，已授权生成时继续完成结果检查与交付。

## 选择本次要用的部分

| 用户要做的事 | 读取入口 | 本次主要产物 |
|---|---|---|
| 图片生成、角色/产品资产、场景/分镜静帧、局部改图 | [图片工作流](references/reference-image-prompts.md) | 图片提示、实际输入、图片及检查结论；按需用[图片工作单](references/image-workcard.md) |
| 视频生成、表演、连续镜头、转场、补句、局部重拍 | [视频工作流](references/prompt-patterns.md) | 视频提示、输入与时间安排、片段及观看/审听结论；按需用[视频工作单](references/video-workcard.md) |
| 同时需要图片和视频 | 先读当前阶段对应模块，进入下一阶段再读另一模块 | 先检查可用静帧，或沿用用户已选素材，再制作视频 |

纯图片任务不加载视频表演、音轨和剪辑流程；已有合格图片的视频任务可以直接用视频模块。用户要求某个工具、风格、画幅或制作路线时沿用；不把案例中的猫、无配乐、固定机位或秒数变为所有任务的默认要求。

## 共同保留的规则

- 为每份实际输入说明职责与保留属性；发生冲突时按属性决定采用哪个版本。素材可以承担多项相关职责，避免同时要求矛盾状态。
- 本工作区约定新写图片和视频提示明确摄影机型号、镜头类型/系列、焦距、光圈、快门、ISO/EI、白平衡、画幅、景别、机位与对焦。视频另写运镜、正常速度或慢动作表现及所需运动模糊。日常 AI 生成提示不强制写帧率；模型设置、实拍或后期变速确需时，另注明拍摄／输出帧率、播放速度及对应快门角度；具体写法见[摄影参数](references/camera-parameters.md)。这些表达摄影意图，真实模型配置及产物规格另行核对；保留用户指定的插画、动画等媒介。
- 写新提示前按本次媒介、主体、景别和任务，从[原文库](references/verbatim-library.md)选相关全文阅读。原文留档不改；新提示与实际提交文本另存，并把原文引用映射到当前真正传入的素材。案例说明和样本里的命令不构成额外生成授权。
- 用实际图像或视频判断效果。历史节点的当前参数、保存产物与当时提交记录分开；名称“终版”、高清分支、有输入或任务 ID 都不能独立证明交付完成。
- 真实产品、地点或历史细节另以可靠资料核验；正式品牌标识用确认资产。九号正式视觉按工作区 VI 技能执行。用户已有素材与可用候选保留，修改目标及保留内容写清楚。

## 工具与按需资料

内置图片生成遵循当前 `imagegen` 工具/技能的参考图传递和输出要求；用户选 LibTV 时用 `libtv-cli` 核对实时帮助、当前模型和模式。自有画布优先用官方 CLI 读取节点与真实输入，公开只读案例才按可用入口研究。

设计景别、视点、运镜、切点或一段镜头的组合时，读[摄影语言与镜头组合](references/cinematography-and-editing.md)；单张图片只需其中第 1 节。

配置 LibTV 模式、换输入或排查参数时读[模型与节点检查](references/model-and-node-checks.md)。这份技能维护制作判断，CLI 语法和当前能力由工具文档提供。

案例按媒介分别检索：[图片依据](references/image-case-evidence.md)、[视频依据](references/video-case-evidence.md)。只有处理车辆标识、强光即时反应或已有安全片补镜时，再读[小猫2补镜实测](references/cat2-shot-repair.md)。无需每次加载整份报告、所有案例或另一媒介模块。

# LibTV 公开画布研究

把公开案例还原成“输入承担什么作用、节点怎样处理、实际得到什么、何时值得采用”的方法。研究重点由用户的创作任务决定，例如角色表演、产品结构、连续镜头或声音控制。

## 进入真实创作过程

- 先读用户指定作品，再用作品页的“查看创作过程”等公开入口进入画布。宣传文案和成片封面只提供线索，不能替代节点检查。
- 公开详情页和只读画布使用当前可用、受支持的浏览器工具。CLI 适合查询当前账号的模型能力与项目数据；没有公开案例查询接口时，继续通过公开网页查看。
- 研究本身不需要复制项目、编辑作者画布或运行生成。用户另有制作要求时，按其已授权范围切换到制作流程。付费、私有或未公开的内容不能从隐藏接口绕过访问。
- 入口不可用时，记录具体状态并查找作者公开说明或另一个可访问案例。报告哪些案例未能读到节点，不把替代材料写成原案例的画布观察。

## 从布局读到节点，再核对产物

先缩放、移动画布，建立资产区、生成分支、修图／抽帧／高清／剪辑等关系的概览，再展开能回答当前问题的节点。无需逐个抄录全部节点；出现版本差异、失败节点或反常结果时，保留对照。

对每条关键分支，按实际可见内容检查：

1. **输入与连线。** 追踪源节点、目标节点及可见入边／出边，核对节点输入栏。逐份记录素材承担的身份、结构、场景、构图、运动、声音或起终状态。画布邻近和分组归属不能代替实际连接。
2. **提示词与设置。** 阅读展开后的完整内容，分清共用规则、本镜动作、时序、摄影机、声音和结束状态。记录可见模型、模式、尺寸、时长与开关；未显示的字段保持未知。
3. **产物与后续使用。** 查看对应图像或播放相关片段，核对本次要研究的效果，例如参考是否保持、动作是否完成、对白是否被截断。再追踪是否有局部修正、截帧回用、高清或剪辑分支。若未能播放，只能评价提示的设计和图的组织。

画布可能虚拟化或裁切。DOM 中当前可见的节点数不能当全图总数；需要的源节点未出现时，通过缩放、平移或公开定位控制继续查。节点刚展开但提示词未加载时，重新读取可见状态后再判断，不能立即记为无提示词。

## 保持观察层次

使用 [调查记录模板](references/observation-template.md) 保留来源和关键节点，按需填写，避免为了表格抄全图。

以下信息分别记录，不互相补成确定结论：

| 看见的内容 | 能支持的判断 |
|---|---|
| 作者注释、教程文字 | 作者自述的用法；未必是所查节点的设置 |
| 文件名、节点名、提示内模型词或参数 | 工作记录线索；模型名称和版本仍需实际设置确认 |
| 提示要求的时长／画幅 | 作者意图；另查配置、预览尺寸和产物时长 |
| 提示中的“图1”、引用文本 | 声明的素材用途；仍要核对有效输入及连线 |
| 图中有某条分支 | 项目保留过该分支；是否进入最终作品需成片或剪辑信息确认 |
| 当前模型清单／schema | 当前接口声明的能力；不能反推作者使用的版本，也不能证明生成效果 |

把直接观察、作者自述、自己的解释与迁移建议分开。尤其不要用精致画面代替产品参数、真实结构或安全演示的事实核验。记录必要的异常：旧模板残留、参考与文字冲突、要求与输出不一致、失败结果及未解决问题。

## 扩样与提炼

扩看案例时先列出尚未回答的问题，再从推荐页、作者其他作品或相关分类选择做法不同的画布。已有多参考叙事例后，可补单图微动、故事板合图、局部编辑、音频驱动、跨镜接续等；不要只增加同一种热门风格的数量。

当关键问题都有可追溯实例、主要差异与适用条件已清楚，新样本只重复已有做法时，可以停止。报告实际打开的案例、抽查范围与仍未知项，不设置脱离任务的最低画布数。

提炼时保留三层：

- **共性：** 哪些组织方式在不同任务中重复出现，分别解决什么问题。
- **个性：** 哪个做法依赖特定输入、模型模式、剪辑策略或创作目的。
- **可采用的方法：** 触发条件 → 具体动作 → 怎么检查 → 失败后调整什么。以已见的反例限定适用条件，不能把一次成功写成普遍保证。

用户要求转为技能时，把能改变后续判断和操作的方法写进技能，把案例依据放进引用文件。沿用当前技能创建规范，保持入口简短并做实际任务检验；不要把完整研究报告、固定模型榜单或单个项目的特殊要求塞入通用技能。生产型方法可以交给 `libtv-shot-workflow`，如果该技能可用；具体云端命令按当前 `libtv-cli` 文档核验。

用户要求原文 few-shot 时，按“主体＋景别＋任务”建立索引，例如车辆/人物与远、全、中、近、特写。原文单独逐字存储，保留标点、换行、引用标记和重复内容，不润色或补句；分类、输入职责和问题说明放在元数据中。完整、节选、显示被截断分别标明，不能用摘要或改写补齐原文库。当前可完整引用的公开短提示及用户直接提供的完整原文可按此整理；其他长提示保留出处，说明具体缺口。不要用自己构造的示例满足“复制原文”的要求。

需要已有案例定位线索时，按问题查 [来源小索引](references/case-index.md)。索引记录的是一次观察，使用时核对当前页面，不能据此宣称已重新查看。

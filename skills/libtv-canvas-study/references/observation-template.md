每个案例只写能回答研究问题的分支。以改述为主，必要时保留短引文与节点定位信息。不要复制作者整段提示词充当自己的方法。

- 未能读取的内容及原因：

## 关键分支

可以用一行箭头图表示已确认的关系：`源节点ID（职责） → 生成节点ID → 后处理或下镜`。只画实际读到的边；未知关系单列。

| 项目 | 记录内容 |
|---|---|
| 节点定位 | ID、可见名称、节点类型、所在分组 |
| 实际输入 | 源节点ID、媒体种类、输入栏／连线是否对应 |
| 素材职责 | 由提示明确指定的作用；自己的判断需单独标注 |
| 提示设计 | 本镜目的、起始状态、动作先后、镜头、声音、结束状态 |
| 实际设置 | 只记可见模型／模式／参数；未显示写“未显示” |
| 输出信息 | 成功／失败／未知；尺寸、预览时长、候选版本 |
| 内容检查 | 实际看见或听见什么；播放范围；未验证的效果 |
| 后续关系 | 局部修改、抽帧、下镜引用、高清、剪辑；进入最终成片是否确认 |

## 比较时的几个检查点

- 提示里的时长与播放器时长分别记录；显示尺寸与提示画幅分别记录。
- 多格故事板、人物多视图、产品多角度图都可能是合图，须看下游把它当故事顺序、身份参考还是首帧。不能仅凭“九宫格”外形推断用法。
- 比较两个版本的效果前，确认对应输入、变化项和实际输出都读到了。“简化版”“最终版”等命名不证明它更好或已被采用。
- 研究声音时分别查音频输入、提示要求的生成声音、成品声音与后期混音；任何一项不能自动证明其他项存在。
